Selected work · Updated May 2026

Production agents. Real operators. Measurable ROI.

Multi-agent AI systems currently running in client operations. Each one started with a workflow map, a baseline measurement, and a clear ROI threshold. The model came last.

01 · Property management

Property Management Intake & Booking Agent

Client: Lakeside Rentals · Stack: Gemini · n8n · Google Workspace · RAG over property SOPs

Gemini-grounded agent framework that ingests inquiry emails, qualifies guests against availability and pricing rules in Google Sheets, drafts a personalized response, and writes confirmed bookings to Calendar.

Critically, the RAG layer enforces a strict data boundary: the agent can only answer from property SOPs, which eliminates hallucinated amenities and policies that could create liability. Every reply is grounded in customer data, not the model's pre-training.

Outcomes

  • Same-hour qualified-reply rate on inbound inquiries, including overnight and weekend traffic.
  • Zero hallucinated property facts since the RAG layer was put in front of the model.
  • Daily KPI roll-up to a single owner dashboard, replacing manual spreadsheet maintenance.
02 · Roofing & exteriors

Roofing Intake & Qualification Governance Framework

Client: Stonecastle Roofing, Hill Country · Stack: n8n orchestrator · Gemini · GoHighLevel · multi-channel intake (web, phone, SMS)

Multi-channel lead capture routed through an n8n orchestrator. A Researcher agent enriches the lead, a Qualifier agent applies the SOP rubric, and an Outreach agent drafts a follow-up email grounded in the company's pricing sheet and service area. Output is logged back to the CRM with a confidence score for human review.

Before any AI was layered in, I mapped the full lead-to-revenue workflow end-to-end and identified the four highest-leverage bottlenecks. Standardized metrics (lead quality score, response time, conversion rate, cost per qualified lead) were defined first. The agent is a thin layer on top of a system that already works.

Governance built in

  • Explicit role separation between enrichment, qualification, and outreach agents to contain failure modes.
  • Every AI-drafted communication logged with a confidence score so a human can spot-check before send.
  • Data scope and aggregation rules enforced at the framework level rather than in the prompt.
03 · Service operators

24/7 Emergency-Response Dispatch Agent

Client: Service operators with after-hours emergencies · Stack: Gemini · n8n · SMS gateway · Google Sheets on-call roster

Designed for service businesses with after-hours emergency calls. The agent triages caller urgency, pulls the correct on-call technician from a shared Google Sheet, sends SMS dispatch, and posts a structured ticket back to the CRM.

Built with explicit human-in-the-loop checkpoints for high-risk routing. Anything irreversible — rolling a truck, paging an owner at 2 a.m. — goes through a confirmation step. The agent is fast where speed matters, and deliberate where mistakes are expensive.

04 · Owner-operators

Owner-Operator KPI & Reporting Agent

Built at: PointWake Innovations · Stack: Orchestrator + RAG over CRM, booking, and accounting data · Google Sheets output

Natural-language interface over CRM, booking, and accounting data. Owners ask questions like "show me last week's revenue by property" and an Orchestrator agent routes the query to the right RAG-backed data source, then returns a chart-ready answer in Google Sheets.

Built to keep non-technical operators inside their data without writing SQL. Strict access boundaries mean the agent can answer about the owner's own data, and only that data — the kind of guardrail that matters the moment an AI tool touches anything regulated or identity-sensitive.
